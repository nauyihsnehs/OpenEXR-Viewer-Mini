<a id="feature-inventory-and-evaluation"></a>

## 功能清单与评估

完整性标记：

- **S（已实现）**：源码中有入口、正常流程及相关失败处理和状态管理。这是实现证据，鲁棒性仍需运行验证。
- **L（有限支持）**：已经实现，但有明确的支持边界，或仍需平台适配工作。
- **F（已修复）**：已在源码中修复明确缺陷，运行验收尚未执行。

重要性按查看、诊断和转换工作的价值分为**必需、重要、可选**。
冗余性分为**独立能力**、**便利入口**（同一能力的另一种操作方式）和**实现重复**（可精简共享代码）。
本轮保留所有功能。结论中的“待验收”表示仍需运行验证；“注明限制”表示文档必须明确支持边界；
“验证修复”表示已完成源码审查，但发布前仍须编译并完成人工验收。

下表列出源码实现和静态审查入口。按维护者决定，本次整理已删除自动化回归及基准源码、
Qt Test／CTest 构建入口；后续验证依赖静态审查和下文人工验收清单，不再以已删除的测试函数作为覆盖证据。
主要交互入口位于 [`src/view`](../src/view)，
导出位于 [`src/io`](../src/io)，输入和显示模型位于 [`src/model`](../src/model)。

<a id="explicit-unsupported-scope"></a>

## 明确不支持的范围

- Deep Tiled 输入，以及使用 `ZBack` 的 Deep 体积语义。
- 逐像素列出或编辑全部 Deep 样本；目前展示合成结果、诊断和源数据摘要。
- Radiance XYZE、序列播放、标准输入／管道输入。
- 由无关文件拼接立体图像、猜测左右眼标签或使用有歧义的配对。
- 完整的色彩管理／OCIO 编辑流程。
- 导出时重建 tiled mip/rip 金字塔；原始数据导出仅以 Scanline 保存所选层级。
- 任意 Deep multipart 平面合并、用 RGBE 无损保存 EXR alpha 和任意通道，或对整组曝光包围文件提供全成或全败的事务。
- Linux/macOS 上的原生 HDR 呈现和资源管理器集成。

Windows 资源和 D3D 库已置于 `WIN32` 条件下。共享查看器代码使用 Qt 文件设备，
EXR 写入不再依赖文件名的本地代码页转换。Shell 的静态 `/MT` 构建继续与主程序的共享依赖隔离。
项目 CMake 最低版本统一为 3.18。

`build_windows.ps1` 是唯一 PowerShell 入口，依次获取缺失源码、增量构建共享与可选 Shell 静态依赖、
编译主程序与 Shell、部署运行文件并按需打包。源码位于忽略的 `dependencies/`，全部构建产物位于 `build/`。
已有缓存保留生成器、工具集、VS 实例及各目录的平台字段；平台为空时不再强加 `-A x64`。
新目录选择已安装、含 C++ x64 工具且当前 CMake 支持的最新稳定版 VS，也可通过 `-Generator` 指定。
主程序、共享依赖及启用的 Shell 构建配置冲突时明确报错，不自动删除目录。
配置后通过编译器元数据检查 MSVC／64 位，再开始构建；Shell 子项目也保留已有的平台字段。
VS 2022 生成器要求 CMake 3.21 起，VS 2026 要求 4.2 起，详见[开发指南](development.md#visual-studio-selection-and-existing-builds)。
选择新版 VS 不代表该工具链与当前 Qt、依赖及打包流程已经通过运行验收。

旧 Snap 配置及重复图标已删除。Linux 仍有分发元数据待整改：AppStream 含无效日期
`2023-05-40`，桌面入口将应用版本误作桌面规范版本，MIME 集成主要覆盖 EXR，未覆盖新增的 HDR 输入。
安装路径和共享库发现仍需原生构建及打包审查。这些属于延期处理的 Linux 分发问题，尚不能据此宣称已验证支持。

macOS 保留 bundle 资源和部署流程，但旧 bundle 标识、RPATH 和部署工具参数仍需实际检查。
移除强制 10.9 不等于应用包已可用。Qt 6.11 官方最低目标为 macOS 13；架构和部署目标须与全部依赖匹配。
参见 [Qt 6.11 支持的平台](https://doc.qt.io/qt-6.11/supported-platforms.html)。

### 通用操作与失败场景

- 用单个脚本检查首次获取依赖、重复增量构建、删除 `build` 后重建、下载中断和编译／部署失败；确认源码保留。

- 复用平台字段为空及显式 `x64` 的旧缓存；检查新目录的 VS 2022／2026 自动选择、旧 CMake 与多个 VS 共存、缺少 C++ 工具、显式生成器冲突、混合缓存和 `-WithoutShell`。核对主程序、共享依赖及 Shell 使用一致工具链，错误时保留已有目录。

- 在解码／渲染中反复关闭和刷新；工作线程结束后释放源句柄和内存。检查移动后的预览标签页、焦点及键盘操作。

层级滑块在松开后加载。加载时，滑块显示请求的位置，菜单显示已提交状态；
禁用层级控件时，不替换控件，也不丢失焦点或工具栏滚动位置。标签变化不应移动滑轨。
方向键／Home／End／滚轮改变层级时，不应同时缩放画布。全部预览页应统一提交。
Fit 重新计算，手动缩放和中心位置保留，极简模式保留小窗口和底栏。
覆盖适应窗口倍率超过 6400% 时反复操作滑块、排队请求被新请求替代、立体预览，
以及可用层级为交集的混合 part 数据源；不能凭空生成层级笛卡尔积。
原始导出将所选层级写为单层 Scanline 图像。

<a id="environment-images-and-projection-conversion"></a>

### 环境图与投影转换

| 样例 | 检查要求 |
|---|---|
| OrientationLatLong | 1024x512；中心 +Z、上方 +Y；方向文字可读 |
| OrientationCube | 512x3072 竖向立方体布局，面顺序为 +X,-X,+Y,-Y,+Z,-Z |
| WavyLinesLatLong | 1024x512；环绕接缝和极点 |
| WavyLinesCube | 256x1536；立方体面边缘和角点 |
| StageEnvLatLong | 1000x500，ROUND_UP 层级 |
| StageEnvCube | 256x1536 |
| KernerEnvLatLong | 1024x512 |
| KernerEnvCube | 256x1536 |

- 检查显式 `envmap` 的优先级，以及对无标记、完整、正方形像素、2:1 彩色图像的保守推断；排除 Deep／立体数据源。初始显示原生布局，旋转不修改源数据。
- 透视视图中，图像内滚轮改变视场角（默认 90 度，范围 10–150），图像外滚轮缩放。球面是无光照的正交投影。重置恢复相机 +Z／+Y 方向，不改变其他显示参数。中键拖动平移；底栏滚轮不得误触按钮，Ctrl+滚轮保留颜色控制行为。
- 交互渲染最长边限制为 512 像素，同时仅有一个请求执行，请求频率约每秒 30 次。拖动松开后恢复完整质量，滚轮停止约 150 ms 后恢复。逻辑画布保持稳定，持续交互不能导致一直没有新帧。缓存的源线性颜色和全源统计不应变成投影裁剪区域的统计。
- 原生读数为精确源采样，转换投影读数为插值结果。球面圆盘外透明，诊断仍基于源数据。检查 StageEnvLatLong 的 (7,7)=8x4 层级在高倍率适应窗口和反复层级切换时的行为。
- 面宽 512 的立方体在第 9 层为 1x6；面宽 256 的在第 8 层为 1x6。后续 1x3／1x1 层仍可原生查看和原始导出，但无法提供六个完整面用于投影。
- 转换尺寸：LatLong 为 4N×2N，竖向立方体为 N×6N，球面为 2N×2N；透视宽高独立。PNG 保留覆盖 alpha，JPEG 合成所选背景。EXR 为显示原色下的线性 FLOAT/ZIP，原点为零、像素比例为一；仅 LatLong／立方体写入 `envmap`。源标量通道名为 A 时，用 `coverage.A` 保存覆盖范围。
- 保存时须捕获当时的投影、相机和颜色选项，并使用完整质量。标记遵循输出尺寸规则。投影转换不应改变源 HDR、曝光包围、原生／原始导出行为。

<a id="deep-scanline-all-twelve-source-files"></a>

### Deep Scanline：全部 12 个源文件

检查 LeftView、LowResLeftView、Stereo 中的 Balls、Ground、Leaves、Trunks。
这些文件包含 1x1 采样的 RGBA HALF 和 Z FLOAT，没有 ZBack，各 part 的数据窗口独立。
LeftView／Stereo 的显示尺寸为 1920x1080，LowResLeftView 为 1024x576。

| 样例组 | 检查要求 |
|---|---|
| Balls | 样本进入／离开包含端点的深度范围时正确合成 |
| Ground | 深度裁剪和空的选中区域 |
| Leaves | 密集样本、取消和内存策略 |
| Trunks | 边缘及较窄的右眼数据窗口 |

- 默认范围覆盖所有有限深度。相同深度按源顺序稳定排序；空像素／范围不包含选中样本。恒定范围禁用调整。当前提供合成查看，不提供样本表编辑。
- 保留预乘颜色中的自发光值。无效深度计入诊断和 Z 标记，但不作为普通有限样本参与合成。自动范围覆盖所选数据。检查 1 GiB 缓存策略、溢出防护和取消。
- 刷新时，完整范围选择重新计算；手动范围则限制到新边界内。颜色重置不改变深度选择。立体预览继承深度策略，先分别合成双眼，再生成红青结果。
- 原始 Deep 输出保留全部原生样本，不受预览筛选影响。检查受支持的 ZIPS 输出、精度及颜色选择所需的 A/Z 依赖；拒绝缺少必需通道的选择和不支持的 Deep 平面合并。移除可选元数据后仍须保留结构元数据。
- 随附的平面合成图可作参考，但不要求与查看器当前的点样本合成策略完全一致。

<a id="radiance-rgbe"></a>

### Radiance RGBE

覆盖未压缩像素、现代 RLE、旧式 RLE、全部 8 种扫描方向和两种可接受的文件标识头。
包含错误宽度、截断流、零长度／过长游程和旧式移位溢出。明确拒绝 XYZE。
验证或拒绝 PRIMARIES 和像素比例，确保各输入阶段仍可取消。
检查黑色、渐变、饱和／高光值及方向，再按 RGBE 的精度和范围限制进行 HDR 导出后重读。
保留解析出的头部信息，描述性曝光字段不得静默改变已存储样本的读数。

<a id="windows-hdr-hardware"></a>

### Windows HDR 硬件

- 在兼容显示器上启用 HDR；在 SDR 显示器或不支持／故障设备上检查明确的 SDR 回退。
  相同 EV 下，线性 RGB 1 对应 Windows SDR 白电平，RGB 4 在未达到峰值时应有预期相对亮度；+1 EV 在裁剪前使线性强度翻倍。
- 检查 Windows 白电平读取、80 nit 回退和约一秒一次的更新。静态审查无法验证 D3D 着色器／交换链。
- 在 HDR／SDR 屏幕间移动窗口，改变 DPI、调整大小、最小化／恢复、切换极简模式；检查界面叠加层、异常标记及全部源／模型类型。
- NaN/Inf 不得使 GPU 输出异常。资源过大、设备丢失和呈现失败时应显示回退原因；显式重试不得形成失败循环。
  复制／PNG/JPEG 使用相同 EV 的 SDR 输出，不将 Windows 桌面白电平缩放写入图像。

### Windows 集成与交付

移动便携目录、多副本、DLL 占用、升级、卸载、资源管理器取消／生命周期、不支持图像的预览回退及系统策略限制。
